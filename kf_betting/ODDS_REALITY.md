# ODDS_REALITY.md — разведка коллектора кэфов winline по CS2

Разведка **исполнением**, 2026-09-14. Проверялось, что коллектор реально способен
собрать по CS2 с winline.kz. Где реальность расходится с INVENTORY.md — здесь
написана реальность.

Итог одной строкой: **линия по CS2 течёт густо, все четыре целевых рынка есть,
closing line ловится, серверный timestamp присутствует. winline пригоден как
источник CS-кэфов.**

> **Примечание 2026-11-19 (подготовка к публикации).** Скрипты `wl_cs_tor.py` и
> `wl_match_tor.py`, на которые ссылается раздел с командами ниже, **на диске
> отсутствуют** — ни в `kf_betting/`, ни где-либо в `~/projects` вне venv. Команды

## 1. Условия запуска: что реально нужно

### Что нашлось в репозитории (шаг 0)

Прочитаны `README.md`, `config.py`, `main.py`, `fetcher/ws_client.py`,
`fetcher/market_cache.py`, `fetcher/human_delay.py`, `parser/event_processor.py`.

| Предусловие | Факт |
|---|---|
| `.env` / `.env.example` | **отсутствуют** — переменных окружения не требуется вообще |
| `vault/` | в `kf_betting` **нет** (есть в соседнем `cs_edge`, это промты, к запуску не относится) |
| прокси / VPN в коде | **нет ни одного упоминания** во всех трёх проектах (grep по `proxy|vpn|socks|tor|getenv|environ`) |
| логин / токены | **не нужны** — WS отдаёт поток анонимно |
| зависимости | `websockets>=12.0` (есть 15.0.1), `playwright` — только для справочника рынков |
| заголовки | `Origin: https://winline.kz`, UA Chrome 126, `Referer: /sport/live` из `config.HEADERS` |
| обёртки запуска | README предлагает `/tmp/pw_venv`, но системного Python достаточно |

Совместимость проверена: `ws_client.py` вызывает `websockets.connect(...,
additional_headers=...)` — сигнатура актуальна для websockets 15.

### Гео и достижимость

**VPN не нужен.** Адрес уже казахстанский:

```
прямой выход: <REAL_IP>  <REAL_GEO>
DNS:          ws.winline.kz -> 185.94.109.114
```

WS `wss://ws.winline.kz/ws/?EIO=4&transport=websocket` поднимается с первой
попытки, без логина, без челленджа:

```
0{"sid":"_84giwMjtzNyva9gA0iB","upgrades":[],"pingInterval":25000,"pingTimeout":20000,...}
40{"sid":"pdReoRi9TCK0yS-0A0iC"}
```

Протокол из `ws_client.py` подтверждён полностью: Engine.IO handshake → `40` →
`42[event, payload]`, серверный ping `2` раз в 25 с, ответ `3`.

### Анонимность (проверено по требованию)

В сети найдена и **задействована** настройка анонимизации:

| Компонент | Состояние |
|---|---|
| `tor@default.service` | active + enabled, SOCKS5 на `127.0.0.1:9050` |
| `/etc/proxychains4.conf` | `strict_chain`, `proxy_dns` → `socks5 127.0.0.1 9050` |
| `torsocks`, `openvpn` | установлены; VPN-конфигов и tun/wg-интерфейсов нет |
| маршрут по умолчанию | прямой через `wlan0` — **прозрачной торификации нет**, заворачивать нужно явно |

Прогон через Tor подтверждён авторитетно (`check.torproject.org/api/ip`):

```
реальный <REAL_IP>  →  выход 192.42.116.45   IsTor=true
```

Доказательство на уровне сокетов во время сбора — у процесса-сборщика
**единственный** сокет, и тот на локальный Tor:

```
ESTAB  127.0.0.1:45590 → 127.0.0.1:9050   users:(("python3",pid=137599))
прямых соединений с 185.94.109.114 во всей системе: 0
```

Реализовано как **fail-closed**: `tor_guard.preflight()` до любого сетевого
действия проверяет живость SOCKS5, отличие выходного IP от реального и флаг
`IsTor`; при любом несовпадении процесс печатает `[ОТКАЗ]` и завершается, **не
подключаясь к winline**. Имя хоста резолвит выходная нода (`dest_host`
передаётся в SOCKS5-запрос), поэтому DNS-утечки нет.

Что через Tor работает, а что нет:

| Ресурс | Напрямую | Через Tor |
|---|---|---|
| WS-поток `ws.winline.kz` | ОК, ~20 соб/с | **ОК, без деградации** (768 событий за 45 с) |
| `winline.kz/sport/live` (HTML) | 200 | 200 |
| `sb/api/markets/list` (curl) | 401 | 401 |
| `sb/api/markets/list` (браузер) | — | **200** |
| `winline.kz/api/init/app-event`, `/api/user/v2` | — | **403** |

Существенная деталь: сайт гоняет запрос к `ipqualityscore.com` (коммерческий
детектор прокси/VPN/Tor), и два собственных эндпоинта под Tor отдали 403.
На спортивную часть (`/sb/api/*`) и на WS это **не повлияло** — они отработали
штатно. Списки exit-нод публичные, так что факт использования Tor скрыт не будет,
хотя исходный адрес — да.

**Оговорка о честности:** самые первые пробы (90-секундный discovery-снимок,
один `curl` к `markets/list` и первый 13-минутный съём CS2) ушли **напрямую с
KZ-адреса**, до того как анонимизация была включена. Весь последующий сбор —
через Tor. Данные от этого не зависят: оба среза дали идентичную картину.

### Профиль нагрузки на сайт

Замерено: WS-сбор — это **одно** TCP-соединение и **один** HTTP-запрос (апгрейд).
Дальше сервер пушит сам; с нашей стороны уходит `40` один раз и однобайтовый
pong `3` раз в 25 с. **Ноль обращений к API, ноль загрузок страниц.** Входящие
9.5 МБ / 90 с — это широковещательная рассылка по всем видам спорта, а не наша
активность. Со стороны сайта выглядит как одна открытая вкладка лайва.

Шумная часть — только справочник рынков: одна загрузка страницы матча в браузере
(она же тянет `markets/list` и `outcomes/list`). Делается однократно.

## 2. Течёт ли CS-линия

**Да, густо.** Два независимых съёма: 13 мин напрямую + 15 мин через Tor.

- CS2 на winline живёт в `sport.id=100248` (Киберспорт) → `category.id=**102357**`
  (Counter-Strike). В `sb_fixture_change` есть `eSportWidget.type="CSGO"`.
- За сессию в потоке было **8+ CS-событий одновременно** (CCT. EU, European Pro
  League, StarLadder StarSeries, WINLINE MPKBK CIS LAN, H2H Liga 2x2 и др.).
- На одно живое событие — **до 80 рынков** в тике, `activeMarketsCount: 26`
  по фикстуре.
- Всего наблюдалось **80 различных `market_id`** по CS2.

Ликвидность по живой карте — **медиана 4 с между обновлениями цены**, минимум
0.3 с. Это не «тонко», это полноценная лайв-линия:

| Рынок | Медианный интервал |
|---|---|
| Фора по раундам (текущая карта) | **4.0 с** |
| Тотал раундов (текущая карта) | **4.8 с** |
| Победитель карты | **3.7 с** |
| Фора по картам | 4.8 с |
| Тотал карт | 4.2 с |
| Победитель матча | 2.5 с |

Рынки уже сыгранных карт, разумеется, замирают (карта 1 при живой карте 3 —
интервал в часах). Это ожидаемо, а не дефект.

**Счёт приходит.** `sb_fixture_change` несёт `match.stats`:

```json
{"map_name": "Anubis", "home_score": 1, "away_score": 1, "match_status": 143,
 "period_scores": [{"number": 1, "home_score": 13, "away_score": 6,  "match_status_code": 141},
                   {"number": 2, "home_score": 13, "away_score": 16, "match_status_code": 142},
                   {"number": 3, "home_score": 8,  "away_score": 8,  "match_status_code": 143}]}
```

То есть **пораундовый счёт по каждой карте отдельно** — ровно то, что нужно для
режима B. Коды: `match_status` 141/142/143 = идёт карта 1/2/3, **100 = матч
завершён**. Переходы карт видны в потоке явно.

Бонусом в фикстуре: `video`, `elStreams` (twitch/kick), `sportlevel`,
`scheduled` (ms), `tournament`, `competitors` с id команд.

## 3. Словарь CS-рынков (главный результат)

Справочник **добыт целиком, путь A сработал**. В браузере (через Tor) при
открытии страницы матча фронт сам дёргает:

- `GET /sb/api/markets/list?query[provider]=internal&query[state]=1&pageSize=5000`
  → **4415 рынков**, `{"id": ..., "name": ...}`
- `GET /sb/api/outcomes/list?...&page=1..8` → **37 491 исход**

Оба отдают **200**. Ручная сшивка по значению кэфа (путь B) не понадобилась.

> Расхождение с INVENTORY: «401 из-за Cloudflare» верно **только для curl**.
> Из настоящего браузера эндпоинт живой. Причина пустого `market_names` в старой
> БД — не блокировка, а неработавший Playwright-путь.

### Важные структурные факты

1. **Номер карты живёт в `specifiers` как `mapnr=N`**, а также в имени рынка
   («3 карта - Тотал раундов»). Отдельных событий на карту нет — вся серия в
   одном `event_id`.
2. **Имена исходов — шаблоны с подстановкой**: `12` = `"Больше {total}"`,
   `1714` = `"П1 ({+hcp})"`, `310437` = `"3 карта - {$competitor2} тотал"`.
   Подставлять нужно из `specifiers` и `competitors`, иначе имя бессмысленно.
3. **У `Победитель` два разных набора исходов**: `4`/`5` (без ничьи) и
   `1`/`2`/`3` для варианта «без ОТ» (там ничья возможна). Резолвер обязан
   различать по `market_id`, а не по числу исходов.
4. Пространство `market_id` для CS — **шестизначное** (`3xxxxx`), плюс немного
   низких общих (`16`, `18`, `19`, `20`, `186`, `220`, `229`, `327`, `328`).

## 4. Closing line и timestamp

### Серверный timestamp — есть, в двух местах

- **на уровне рынка**: `markets[].timestamp` — присутствовал в **6735 из 6735**
  наблюдённых рынков-тиков, ни одного пропуска;
- **в корне payload**: `sb_odds_change.timestamp` — во всех 281 событиях;
- в фикстуре: `match.timestamp` и корневой `timestamp`.

Формат — **Unix ms** (`1789393578634`). Разные рынки внутри одного события могут
иметь разный timestamp, так что брать нужно рыночный, а не корневой.

Замеренный «лаг» `recv_ts − server_ts` = медиана 82.96 с при разбросе 82.2…83.0
оказался **не задержкой доставки, а уходом локальных часов**: сверка с заголовком
`Date` самого winline дала **+83.0 с** расхождения системного времени. Реальная
задержка доставки ≈ 0. Вывод: **синхронизировать локальные часы (NTP) или считать
серверный timestamp единственным авторитетным временем.**

### Статусы рынка — по факту

| `market.status` | смысл | наблюдений |
|---|---|---|
| `1` | активен, кэфы есть (13 535 котировок, ни одной пустой) | 5776 |
| `0` | **suspended**: 428 раз приходит с *пустым* `outcomes` (чистый флаг снятия), 264 раза с ценами (пауза при сохранённой котировке) | 692 |
| `-3` | **settled/рассчитан**: кэфов нет никогда, исходы несут `result: true/false` и `active: false` | 267 |

Наблюдённые переходы: `1→0` — **394 раза**, `0→1` — 276, `0→-3` — 2.
Отдельно приходит `sb_bet_stop` с `meta.tradingStatus: -1` и
`sb_bet_settlement` — последний несёт итоговый расчёт с флагом `result` по
каждому исходу, то есть **резолв ставки можно брать прямо из потока**, не считая
его самостоятельно по счёту.

### Closing line — ловится

Поймано **394 закрытия рынка**. Разрыв между последней живой котировкой и
снятием рынка:

```
медиана 11.8 с    p10 1.1 с    p90 47.3 с    максимум 255.6 с
```

Примеры реально пойманных клоузов:

```
3 карта - Тотал раундов   mapnr=3|total=29.5   [5.36, 1.12]  снят через  1.8 с
3 карта - Фора по раундам hcp=4.5|mapnr=3      [1.04, 8.00]  снят через  8.3 с
3 карта - Тотал раундов   mapnr=3|total=21.5   [1.15, 4.77]  снят через  6.1 с
```

**Механика захвата понятна и надёжна:** последний тик со `status=1` и непустыми
кэфами — это и есть closing line; следом приходит тот же рынок со `status=0` и
пустым `outcomes`, что служит явным маркером «здесь закрылось». Ничего
угадывать по таймеру не нужно. Единственное требование — писать **каждый** тик,
а не дельту по изменившейся цене, иначе последний перед снятием может потеряться.

## 5. Расхождения с INVENTORY.md

| Утверждение INVENTORY | Реальность |
|---|---|
| «CS2-событие дало 0 тиков odds» | **Опровергнуто.** Линия течёт с медианой 4 с. Ноль в старой БД — следствие фильтров/резолвера, а не отсутствия потока |
| «справочник не подгрузился, всё `market_<id>`» | Подтверждено как следствие, но **причина другая**: эндпоинт живой и отдаёт 200 из браузера; не работал Playwright-путь |
| «`markets/list` → 401 из-за Cloudflare» | Верно только для curl. Из браузера — 200 |
| «серверный timestamp теряется» | **Подтверждено в коде**: `parse_odds_change` кладёт `payload.get("timestamp")` в переменную `timestamp_ms` и **никогда её не использует**; рыночный `markets[].timestamp` не читается вовсе. В самом потоке timestamp есть всегда |
| «closing line не фиксируется» | Подтверждено как пробел кода. В потоке клоуз **доступен** и однозначно маркирован |
| «резолвер захардкожен под футбол `{1,16,25,29,223,225}`» | **Подтверждено и хуже, чем кажется**: из CS-рынков в этот набор попадает только `16`. Остальные ~98 % ушли бы в `outcome_<id>` / `market_<id>`. При этом `25`/`225` в CS не встречаются вовсе, а `310896` («Тотал раундов») мимо ветки тотала не распознаётся |

Дополнительно найдено (за пределами `kf_betting`, поэтому только фиксирую):
`cs_edge/ingest/odds.py::_map_index` использует regex
`(?:карт[аеуы]|map)\s*(\d)`, который на реальных данных **всегда возвращает 0** —
номер карты стоит *перед* словом («3 карта - Тотал раундов»), а в спецификаторах
ключ `mapnr=3`, где после `map` идёт `n`. Проверено исполнением на четырёх
реальных строках: все дали `map_index=0`. То есть все карты схлопнулись бы в
«серию».

## 6. Вердикт

**winline пригоден как источник CS-кэфов.** Ни одного блокирующего препятствия
не обнаружено:

- линия по CS2 **течёт густо** — 4 с медиана по живой карте, до 80 рынков на
  событие, несколько матчей одновременно;
- **все четыре целевых рынка присутствуют** и опознаны по id (`310858-60`,
  `310894-96`, `327`, `328`), причём тотал/фора котируются целой кривой линий;
- **справочник рынков добывается целиком** (4415 рынков, 37 491 исход) —
  захардкоженные словари не нужны;
- **closing line ловится** с явным маркером снятия;
- **серверный timestamp есть в каждом тике** — синхронизация возможна;
- **расчёт исходов приходит из потока** (`sb_bet_settlement`, `result`), плюс
  пораундовый счёт по каждой карте в `period_scores`;
- **транспорт дешёвый и тихий**: одно соединение, без логина, без опроса API;
  работает и напрямую, и через Tor.

Искать другой источник **не требуется**. Непригодным коллектор делает не winline,
а три конкретных места в коде: футбольный резолвер исходов, выбрасываемый
timestamp и отсутствие записи закрытия рынка. Это доработка, и она за границами
этой разведки.

## Приложение: как воспроизвести

```bash
# 1. предполётная проверка анонимности (fail-closed)
python3 tor_guard.py                    # ждём ok=true, IsTor=true

# 2. пассивный съём CS2 через Tor, 15 минут
python3 wl_cs_tor.py cs_tor.jsonl 900   # фильтр: category_id=102357

# 3. контроль во время сбора — утечек быть не должно
ss -tnp | grep "$(pgrep -f wl_cs_tor.py | head -1)"   # только 127.0.0.1:9050
ss -tnp | grep 185.94.109.114                          # пусто

# 4. справочник рынков (однократно, браузер через Tor)
/home/vladi/projects/parcer_cs/venv/bin/python wl_match_tor.py \
  "https://winline.kz/sport/100248/102357/<tournament_id>/match/<event_id>" tag
```

**Справочник сохранён в репозиторий** (снят 2026-09-14 из
`/sb/api/markets/list` и `/sb/api/outcomes/list`):

| файл | содержимое | размер |
|---|---|---|
| `data/dict_markets.json` | 4415 записей `market_id → имя рынка` | 314 КБ |
| `data/dict_outcomes.json` | 37 491 запись `outcome_id → шаблон исхода` | 1.2 МБ |

Это схема, а не наблюдения: без неё все рынки снова станут `market_<id>`, как в
старой БД. По матчам не устаревает; пересниметь имеет смысл лишь при появлении
новых рынков у провайдера. Имена — шаблоны (`"Больше {total}"`, `"П1 ({+hcp})"`,
`"{$competitor1} тотал"`), подстановка из `specifiers` и `competitors`.

Скрипты разведки и сырые дампы потока (`cs_stream.jsonl`, `cs_tor.jsonl`)
остались в scratchpad-каталоге сессии и в репозиторий не клались. Код не менялся,
схема БД не трогалась, наблюдения впрок не собирались.
