## Справка по этой машине (проверено 2026-09-14)

| Компонент | Состояние |
|---|---|
| `tor@default.service` | active + enabled, SOCKS5 на `127.0.0.1:9050` |
| `/etc/proxychains4.conf` | `strict_chain`, `proxy_dns` → `socks5 127.0.0.1 9050` |
| `torsocks`, `openvpn` | установлены; VPN-конфигов и tun/wg-интерфейсов нет |
| маршрут по умолчанию | **прямой** через `wlan0` — прозрачной торификации НЕТ |
| DNS | `127.0.0.1:53` (локальный резолвер) |
| прямой выход | <REAL_GEO> |

Ключевое следствие: **само по себе ничего в Tor не заворачивается.** Пока код
явно не использует SOCKS5, он идёт с реального адреса, даже если `tor` запущен.

## Готовые способы завернуть

```bash
proxychains4 <команда>                 # универсально для CLI
torsocks <команда>
curl --socks5-hostname 127.0.0.1:9050  # DNS резолвит exit-нода (важно)
```

Python (websockets / http):

```python
import sys; sys.path.insert(0, "/home/vladi/projects/tools")
import tor_guard
guard = await tor_guard.preflight()
if not guard["ok"]:
    sys.exit("анонимность не подтверждена: " + guard.get("error", ""))
sock = await tor_guard.connect_via_tor("example.com", 443)
```

Playwright: `proxy={"server": "socks5://127.0.0.1:9050"}`, рабочий интерпретатор —
`/home/vladi/projects/parcer_cs/venv/bin/python` (системный playwright сломан под Node 24).

## Чего проверка НЕ даёт

- Факт использования Tor виден — списки exit-нод публичные; скрыт исходный адрес,
  а не сам факт.
- Логин в аккаунт обнуляет всё: аккаунт идентифицирует тебя сам, IP уже не важен.
- Уже отправленные напрямую запросы отменить нельзя.
- Проверка охватывает процессы сбора; она не аудирует остальной трафик машины.
