> Разведка от 2026-09-16, всё офлайн по фикстуре корпуса. Парсер НЕ писался,

> Закрывает вопрос, который в _STATE стоял как «H2 отложена: нет в лёгких источниках».

## Короткий ответ

ДА. Счёт живых достаётся для ЗАВЕРШЁННОЙ карты постфактум, **прямым чтением, а не
реконструкцией из событий**. Источник ровно один — `match_performance`.

Страница: `/stats/matches/performance/mapstatsid/{map_stat_id}/{slug}`
Гранулярность: **одна карта = один запрос**. `map_stat_id` тот же, что у economy
(в корпусе 237040) → берётся в паре с ней, лишней навигации нет.

## Где именно лежит

В странице ~2800 блоков вида

```html
<div class="tooltip" id="tooltip_player{player_id}_round{N}_event{K}">
  <div class="round-swing-tooltip">
    <div class="team-info">
      <div class="team"><img alt="FOKUS" …><div class="team-stat">89.2%</div></div>
      5 vs 3                                        ← ЖИВЫЕ: team1 vs team2
      <div class="team"><img alt="BC.Game" …><div class="team-stat">10.8%</div></div>
    </div>
    <div class="event-info"> … Banjo killed mzinho … </div>
```

* **`N vs M`** — голый текст МЕЖДУ двумя блоками `div.team` внутри `div.team-info`.
* Порядок команд задаёт сам блок: `alt` у логотипов (team1 первым).
* `div.team-stat` — win-probability каждой команды на этот момент. По ней же
  читается победитель раунда (у кого 100% на последнем событии).
* `div.event-info` — текстом: «кто кого убил», «planted the bomb», «Bomb detonated».

Счёт живых стоит у **каждого** события, а не только в конце раунда:
`5 vs 5` (round started) → `5 vs 4` → `5 vs 3` → …
**Чистота раунда = значение на ПОСЛЕДНЕМ событии раунда.** Всё, что до — бонус
(траектория раунда, если понадобится).

### Лента событий (параллельный источник в той же странице)

`data-chartjs-config` (360 шт: 10 игроков × 35 раундов + 10 bar-графиков),
внутри `data.datasets[0].data` — точки события:

```
{"x":"3","y":"0.8921…","icon":"/img/static/scoreboard/kill.svg",
 "secondaryIcon":"/img/static/stats/roundSwing/t_badge.png",
 "isRelevant":true,"tooltipId":"tooltip_player20625_round1_event3"}
```

* `icon` — тип события: `buy.png` · `kill.svg` · `bombplant.svg` ·
  `bomb_exploded.svg` · `bomb_defused.svg` · `t_win.svg` · `stopwatch.svg`
* `secondaryIcon` — `t_badge` / `ct_badge`: сторона, СДЕЛАВШАЯ килл
* `tooltipId` — связь с тултипом выше
* `y` — win-prob с точки зрения того игрока, чей это график

Лента ОДНА на раунд: у всех 10 игроков она совпадает, различаются только кривые
`y` (две зеркальные — по команде).

## Рецепт (проверен, работает на фикстуре)

```python
import re, html, json

S = open(PATH, encoding="utf-8", errors="replace").read()

# 1) ленты событий: раунд → список событий (берём график любого игрока)
PAT = re.compile(r'tooltip_player(\d+)_round(\d+)_event(\d+)')
rounds = {}
for m in re.finditer(r'data-chartjs-config="(.*?)"', S, re.S):
    o = json.loads(html.unescape(m.group(1)))
    if o.get("type") != "line":
        continue
    ds = o["data"]["datasets"][0]["data"]
    rounds.setdefault(int(PAT.match(ds[0]["tooltipId"]).group(2)), ds)

# 2) тултипы: id → (team1, живые1, team2, живые2, winprob1, winprob2)
TIP = re.compile(r'<div class="tooltip" id="(tooltip_player\d+_round\d+_event\d+)">'
                 r'(.*?)(?=<div class="tooltip" id=|\Z)', re.S)
TI  = re.compile(r'<div class="team-info">(.*?)</div><div class="event-info">', re.S)
ALIVE = re.compile(r'</div></div>(\d+)\s*vs\s*(\d+)<div class="team">')

tips = {}
for tid, body in TIP.findall(S):
    ti = TI.search(body)
    if not ti:
        continue
    names = re.findall(r'<div class="team"><img alt="([^"]*)"', ti.group(1))
    stats = re.findall(r'<div class="team-stat">([\d.]+)%</div>', ti.group(1))
    al = ALIVE.search(ti.group(1))
    if len(names) == 2 and len(stats) == 2 and al:
        tips[tid] = (names[0], int(al.group(1)), names[1], int(al.group(2)),
                     float(stats[0]), float(stats[1]))

# 3) чистота раунда = последнее событие
for rnd in sorted(rounds):
    t1, a1, t2, a2, p1, p2 = tips[rounds[rnd][-1]["tooltipId"]]
    winner, survivors = (t1, a1) if p1 > p2 else (t2, a2)
    # → раунд rnd: победил winner, у него осталось survivors живых
```

Два регэкспа-ключа, на которых всё держится:
* `TI` — вырезать `team-info` до `event-info` (иначе зацепится соседняя разметка);
* `ALIVE` — `</div></div>(\d+) vs (\d+)<div class="team">`: якоря обязательны,
  голый `\d+ vs \d+` ловит мусор со всей страницы.

## Покрытие и стоимость

* **35 раундов** на фикстуре против **24** в economy — performance единственный
  источник, покрывающий ОВЕРТАЙМ (карта 19:16).
* 2800 тултипов = 280 уникальных событий × 10 ракурсов игроков. Покрытие 100%:
  счёт живых есть у каждого события каждого раунда.
* Ещё 350 тултипов вида `tooltip_player{id}_match_round{N}` — это bar-график
  вклада игрока в раунд, счёта живых там нет и не нужно.

| | на диске | gzip (по сети) | разбор |
|---|---|---|---|
| match_performance | 8.5 МБ | **0.4 МБ** | 0.1 с чистым regex |
| economy (сравнение) | 344 КБ | 56 КБ | — |

**Важно: «8.9 МБ» — цена ХРАНЕНИЯ в raw store, не трафика.** По сети страница
весит как обычная страница HLTV. Раздута тем, что в каждый из 2800 тултипов
вклеены CDN-ссылки на логотипы и бодишоты (~19.5 тыс. ссылок на картинки).
DOM-парсер не нужен — regex по 8.5 МБ отрабатывает за 0.1 с.

## Оговорки

* **Выжившие у ПРОИГРАВШЕГО могут быть завышены.** В раунде 1 бомба взорвалась
  при `5 vs 1` — HLTV считает живых на момент РЕШЕНИЯ раунда, а не после урона
  от взрыва. Для метрики «выжившие у победителя» это неважно; если понадобится
  сторона проигравшего — сначала уточнить семантику на карте с взрывом.
* Проверено на ОДНОЙ карте (237040, FOKUS vs BC.Game, 19:16 с двумя ОТ).
  Формат вёрстки на другой карте не перепроверялся — при первом же парсинге
  прогнать ту же сверку с economy как регрессию.
* `map_stat_id` для performance надо откуда-то взять: он приходит со страницы
  матча / L3, отдельного справочника нет.
