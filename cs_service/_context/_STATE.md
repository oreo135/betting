## Цель
Аналитический сервис-витрина прогнозов CS2 (образец продукта — Nb-Bet, но с
раундовой моделью и симулятором, чего у них нет). НЕ букмекер. Первый релиз —
без реальных денег: показывает сигналы → проверяешь глазами → копишь статистику
попаданий → потом деньги.

**УТОЧНЕНО 2026-09-23 (ревизия).** Цель формулируется как ПЛАТФОРМА ПРОВЕРКИ
ГИПОТЕЗ НА ЛАЙВЕ ПРОТИВ РЫНКА, цепочка из четырёх звеньев:
**тянуть из лайва ВСЁ → гибкие модели из сигналов → сверка с кэфом →
отслеживать, где мы правы.**
Следствие для планирования: **форма игрока — ПЕРВЫЙ СИГНАЛ В КОНСТРУКТОРЕ, а не
отдельная фича.** Прежняя формулировка цели (витрина прогнозов) не отменена —
она про продукт, эта про то, на чём он будет стоять.
 
## Ключевые решения (не переоткрывать)
- Сбор ПО ТРЕБОВАНИЮ: выбрал 1-3 матча → парсер тянет точечно (составы + сила по
  пятёркам + форма 10 игроков + вето) + кэфы. НЕ датасет впрок (лимит HLTV).
- База копится САМА от использования (raw store) → со временем = обучающий датасет.
- Три слоя: raw store (сеть только тут) → facts (атомарно, as_of, дедуп) →
  features (на лету, не хранятся) → модель → прогноз vs кэф.
- Цель прогноза: тотал РАУНДОВ, победа, фора, комбо. НЕ тотал килов.
- Одна сущность: факты → p_ct/p_t → симулятор → распределение счёта → все рынки.
- Эталон истины — закрывающая линия. Метрика — CLV + калибровка.

## Математика (заморожена, детали в _MATH)
p_round = sigma( z +/- (m_map + t_team) + g*dForm + b_eco*Eco + d*Prev )
- t_team: из lineup/map (готовый CT/T по пятёрке) — ОСНОВНОЙ путь.
- m_map: общий side-bias карты из /stats/maps (Distribution T/CT wins) — априор для усадки.
- z (сила пары): из lineup/map winrate + усадка по выборке. Glicko/round-history — РЕЗЕРВ.
- форма: отклонение recent-base (иначе двойной счёт), среднее + разброс (form_dispersion).
  [2026-09-17: РАЗМОРОЖЕНА — фаза D лайв-ветки. GAMMA_FORM=0.0 в config.py остаётся
  до D2; замещает прежнее «форма ОТЛОЖЕНА, на старте не подключать».]
- delta: остаток момента сверх экономики; на старте delta=0.
- kappa (килы): НЕ нужно (цель — раунды).
- Усадка по выборке ОБЯЗАТЕЛЬНА: мало Times played → шире неопределённость → осторожный прогноз.
- РЕАЛИЗОВАНО (ДВ-1), детали расчёта:
  * усадка: w = n/(n+lambda), n = раунды пятёрки на ЭТОЙ стороне (total_rounds/2),
    априор = m_map ЭТОЙ стороны (не 0.5!). Пятёрка без данных получает фон карты.
    lambda = 100 раундов — ДЕФОЛТ, не калибровка (EB: lambda = p(1-p)/Var даёт 50-100).
    Живёт в src/config.py, калибровать на ЭТАПЕ 5.
  * свёртка пары в ЛОГИТ-шкале: p_ct(A) = sigma(logit(m_ct) + s_A_ct - s_B_t),
    где s = logit(усаженный wr) - logit(фон стороны). Комплементарность p_A + p_B = 1
    выполняется ТОЧНО и по построению (logit(m_t) = -logit(m_ct)), а не по договорённости.
  * обрезание p_round в [0.20, 0.80], симметрично — иначе ломается комплементарность.

Вместо winline WS (серый ToS + не подтверждено, течёт ли CS2) склоняемся к ODDS API
(OddsPapi: CS2, Pinnacle-эталон, история линии бесплатно, легально). Проверить ключом
на живом матче КОГДА дойдём до фазы кэфов. Winline WS — резерв. Наблюдение потока —
не взлом (публичный поток), но против ToS бука → odds API чище.

* **ЛАЙВ-кэфы идут в ОТДЕЛЬНУЮ БД ДВИЖКА**, а не в таблицу `odds` базы фактов.
  Сбор — через parcer_cs (инвариант «сеть только там» не меняется), владение и
  запись — у движка, рядом с лайв-журналом. Таблица `odds` в фактах остаётся под
  пред-матчевую и закрывающую линию, её схему сейчас не трогаем.
* **Привязка лайв-линии — К РАУНДУ**, не только ко времени: иначе линию не

## Предел покрытия (честно)
УТОЧНЕНО: покрытие определяет АКТИВНОСТЬ команды, а не её ТИР. lineup/map тянет по
СОСТАВУ за все матчи в окне, без привязки к турниру — играющая команда из нижнего
дивизиона даёт больше данных, чем tier-1, простоявший месяц после замены.
Прежняя формулировка («tier-2/3 → данных мало») была неверной: она путала тир с
активностью.
Настоящий гейт — **Times played в собранном срезе**, и он виден ТОЛЬКО ПОСЛЕ сбора.
По названию турнира не предсказывается → отбраковывать матчи заранее «по тиру» нельзя.
Что действительно режет покрытие:
  * свежая пятёрка — мало СОВМЕСТНЫХ матчей (свойство состава, не дивизиона);
  * простой команды / межсезонье / пауза после ростер-мува;
  * короткое окно среза (см. решение «окно = месяц» — режет сильнее всего);
  * необъявленный ростер до матча → неизвестно, чью пятёрку запрашивать;
  * редкая для команды КАРТА: Times played считается по карте, не по команде вообще.
Модель это отражает усадкой (мало раундов → ниже вес наблюдения → ближе к фону карты),
не притворяется. Ликвидность линий от тира зависит — но это про РЫНОК (ЭТАП 4-5),
а не про покрытие данными, не смешивать.
